## 1. IDENTITAS & TARGET PROYEK

- **Nama Proyek:** ZeroStunt.id
- **Tujuan:** Sistem web pencegahan stunting yang mengintegrasikan supply chain pangan lokal (kelompok tani → puskesmas → posyandu → ibu/anak) dengan tracking pertumbuhan anak berbasis Z-Score WHO 2006, sekaligus mengeliminasi tengkulak (middlemen) untuk meningkatkan pendapatan petani.
- **Inovasi Alignment:** RIRN 2017–2045 (ketahanan pangan, diversifikasi pertanian lokal) + SDGs Goal 2 (Zero Hunger) + Goal 3 (Good Health)
- **Arsitektur:** MVC PHP Native (zero backend framework), Vanilla JS, Tailwind CSS
- **Deadline:** Minggu ke-2 Juli 2025
- **Tim:** 4 orang, Semester 2, Teknologi Rekayasa Perangkat Lunak, ASTRATECH
- **Status Saat Ini:** Struktur folder + GitHub setup selesai, Tailwind setup in progress, belum mulai coding logic

## 4. KOMODITAS & PAKET GIZI (HARDCODED v1)

**Komoditas (3-4 jenis):**
1. Ikan Nila Segar (Kg) — Protein Hewani
2. Telur Ayam Kampung (Butir) — Protein + Micronutrient
3. Sayur Hijau (Kg) — Vitamin & Mineral
4. Kacang-kacangan (optional, Kg)

**Paket Gizi (HARDCODED, bukan tabel dinamis):**

| Paket | Target | Isi |
|---|---|---|
| Prioritas 1 | Balita 0-24 bulan berisiko stunting + Ibu Hamil | 1.5kg ikan + 10 telur |
| Prioritas 2 | Balita 0-24 bulan gizi kurang | 1.0kg ikan + 8 telur |
| Prioritas 3 | Anak 2-5 tahun, monitoring | 0.5kg sayur + 3 telur |

**Prioritas Assignment Logic (via Trigger):**
```
is_pregnant = TRUE      → PRIORITAS 1 (auto)
Z-Score < -3 SD         → PRIORITAS 1 (Berisiko Stunting)
Z-Score -2 s/d -3 SD   → PRIORITAS 2 (Gizi Kurang)
Z-Score > -2 SD         → PRIORITAS 3 (Normal)
```

## 7. TRIGGERS (5 — CRITICAL BUSINESS LOGIC)

### Trigger 1: after_insert_pemeriksaan
```
Event: AFTER INSERT ON transaksi_pemeriksaan
Logic:
  1. Hitung usia_bulan dari tgl_lahir anak
  2. Lookup standar_pertumbuhan (usia_bulan, jenis_kelamin, 'BB/U' dan 'TB/U')
  3. Z-Score = (actual - median) / sd
  4. Set status_gizi:
     - Z < -3 SD  → 'Berisiko Stunting'
     - Z -2 to -3 → 'Gizi Kurang'
     - Z > -2 SD  → 'Normal'
  5. Set skala_prioritas: 1/2/3 sesuai status
  6. UPDATE anak SET st_gizi_skrg, skala_prioritas
  7. SIGNAL jika usia invalid atau standar tidak ditemukan
```

### Trigger 2: after_insert_pengadaan_detail
```
Event: AFTER INSERT ON pengadaan_detail
Logic:
  1. UPDATE stok_log SET qty_in += jumlah_pasok
     WHERE id_gudang = gudang_pusat AND id_komoditas = NEW.id_komoditas
  2. INSERT stok_log jika record belum ada (UPSERT pattern)
```

### Trigger 3: distribusi_detail (Before + After)
```
BEFORE INSERT:
  VALIDATE stok_log.qty_current (gudang asal) >= jumlah_kirim
  SIGNAL SQLSTATE '45000' jika insufficient

AFTER INSERT:
  UPDATE stok_log (asal): qty_out += jumlah_kirim
  UPDATE stok_log (tujuan): qty_in += jumlah_kirim
```

### Trigger 4: penyerahan_detail (Before + After)
```
BEFORE INSERT:
  VALIDATE stok_log.qty_current (gudang posyandu) >= jumlah_serah
  SIGNAL SQLSTATE '45000' jika insufficient

AFTER INSERT:
  UPDATE stok_log (posyandu): qty_out += jumlah_serah
```

### Trigger 5: after_update_distribusi_status
```
Event: AFTER UPDATE ON transaksi_distribusi_internal
       WHERE status_kirim berubah ke 'Diterima'
Logic:
  Confirm receipt, lock stock, update activity_log
```

## 8. DATABASE VIEWS (4 — UNTUK REPORTS)

```
v_penyerapan_komoditas:
  SELECT komoditas, total_masuk(pengadaan), total_keluar(penyerahan), sisa_stok
  → Report 1: Penyerapan komoditas

v_stok_gudang_realtime:
  SELECT gudang, komoditas, qty_current FROM stok_log JOIN gudang JOIN komoditas
  → Report 2: Stok realtime per gudang

v_tren_pertumbuhan_wilayah:
  SELECT gudang, bulan, AVG(bb), AVG(tb), COUNT(anak) FROM pemeriksaan GROUP BY gudang, month
  → Report 3: Tren pertumbuhan

v_ekonomi_mitra:
  SELECT petani, SUM(total_bayar), SUM(CASE Lunas), SUM(CASE Pending) FROM pengadaan GROUP BY petani
  → Report 4: Ekonomi mitra petani
```

| Report 4 | ✅ | ❌ | ✅ (own data) | ❌ |
| Dashboard | Admin | Kader | Petani | Ibu |

**Data Isolation:**
```
Kader  → filter by gudang_id = $_SESSION['gudang_id']
```

## 11. TEMPLATE RENDERING PATTERN

**BUKAN static HTML. PHP Native template via include:**

```
Request masuk → public/index.php (router)
→ Dispatch ke Controller
→ Controller call $this->render('transaksi/pemeriksaan/form', $data)
→ BaseController::render() extract $data → include view file
→ View file (HTML campur PHP) dieksekusi
→ base.html di-include sebagai wrapper (navbar, sidebar, footer)
```

**Mirip konsep Blade Laravel, tapi MANUAL menggunakan `<?php include ?>`**
