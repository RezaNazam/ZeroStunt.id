## 1. PROBLEM STATEMENT

### Latar Belakang
```
Indonesia memiliki tingkat stunting tinggi (~24% pada 2022)
Stunting = chronic malnutrition (height-for-age < -2 SD WHO 2006)
Dampak: Kognitif berkembang lambat, produktivitas rendah, biaya healthcare tinggi

ROOT CAUSES:
├─ Supply chain pangan lokal tidak terkoneksi
├─ Petani lokal kena tengkulak (margin rendah)
├─ Posyandu tidak track pertumbuhan secara sistematis
├─ Data tracking tersebar, tidak terintegrasi
└─ Ibu tidak tahu anak mereka berisiko stunting sampai terlambat
```

### Solusi yang Diusulkan
```
ZeroStunt.id = Sistem Terpadu:

Supply Chain Integration:
  Petani Lokal → Puskesmas (Gudang Pusat) → Posyandu → Ibu+Anak
  (eliminasi tengkulak, transparansi harga, stabilitas pendapatan petani)

Growth Tracking:
  Kader screening anak (BB, TB, LK) → Auto-hitung Z-Score WHO 2006
  → Auto-set status gizi (Berisiko/Kurang/Normal)
  → Auto-set prioritas paket gizi (1/2/3)

Distribution:
  Otomatis alokasi paket gizi sesuai prioritas
  Tracking distribusi real-time
  Laporan konsumsi & tren pertumbuhan

Innovation Alignment:
  ✅ RIRN 2017-2045: Ketahanan pangan + diversifikasi pertanian lokal
  ✅ SDG Goal 2: Zero Hunger
  ✅ SDG Goal 3: Good Health
```

```
├─────────────────┼──────────────────────────────────┼─────────────────────┤

│ Ibu/Anak        │ Beneficiary, track growth        │ ROLE_IBU (Read-only)│
└─────────────────┴──────────────────────────────────┴─────────────────────┘
```

### Geographic Scope (Pilot Phase)
```
1 Puskesmas = Gudang Pusat (Central Warehouse)
  │
  ├─ 1 Kader = 1 Posyandu (Gudang Lokal)
  │  └─ 30-50 Ibu + Anak per Posyandu
  │
  ├─ Posyandu Melati (Kader: Sari)
  │  └─ ~40 Ibu+Anak
  │
  ├─ Posyandu Mawar (Kader: Dewi)
  │  └─ ~45 Ibu+Anak
  │
  └─ Posyandu Anggrek (Kader: Tini)
     └─ ~35 Ibu+Anak

Total: 1 Puskesmas + 3 Posyandu + ~120 Ibu+Anak + 3-5 Petani

Operational Cycle:
  Screening: 1x/bulan per posyandu
  Pengadaan: 1-2x/bulan
  Distribusi: 1x/bulan sesuai hasil screening
  Reporting: Akhir bulan
```

## 3. ENTITY RELATIONSHIP DIAGRAM (ERD)

### Simplified ERD (Text Format)

```
USERS (Auth Layer)
  ├─ 1 ─── M ─→ IBU (Shared PK: id_user)
  ├─ 1 ─── M ─→ PETANI_LOKAL (Shared PK: id_user)
  └─ 1 ─── M ─→ ACTIVITY_LOG

IBU
  ├─ 1 ─── M ─→ ANAK (Parent-Child)
  ├─ N ─── 1 ─→ GUDANG (Belong to Posyandu)
  ├─ 1 ─── M ─→ TRANSAKSI_PENYERAHAN_BANTUAN
  └─ is_pregnant: trigger prioritas 1

ANAK
  ├─ N ─── 1 ─→ IBU
  ├─ 1 ─── M ─→ TRANSAKSI_PEMERIKSAAN
  └─ st_gizi_skrg, skala_prioritas (auto-set by trigger)

PETANI_LOKAL
  ├─ 1 (User) ─── M ─→ TRANSAKSI_PENGADAAN
  └─ no_rekening, kapasitas_panen_bulan

GUDANG
  ├─ 1 ─── M ─→ IBU (Posyandu warehouse assignment)
  ├─ 1 ─── M ─→ STOK_LOG
  ├─ jenis_gudang: 'Pusat' (1) atau 'Posyandu' (many)
  ├─ Dapat menerima distribusi (dari Pusat ke Posyandu)
  └─ Dapat mengirim distribusi (dari Pusat)

KOMODITAS_PANGAN
  ├─ N ─── 1 ─→ SATUAN
  ├─ 1 ─── M ─→ PENGADAAN_DETAIL
  ├─ 1 ─── M ─→ DISTRIBUSI_DETAIL
  ├─ 1 ─── M ─→ PENYERAHAN_DETAIL
  ├─ 1 ─── M ─→ STOK_LOG
  └─ kategori_gizi: 'Protein Hewani', 'Vitamin', 'Mineral', etc

SATUAN
  ├─ 1 ─── M ─→ KOMODITAS_PANGAN
  └─ nama_satuan: Kg, Butir, Liter, Paket

STANDAR_PERTUMBUHAN (WHO 2006 Static Data)
  ├─ PK: (usia_bulan, jenis_kelamin, tipe_standar)
  ├─ tipe_standar: 'BB/U' (Weight-for-Age), 'TB/U' (Height-for-Age)
  ├─ Lookup dari: TRANSAKSI_PEMERIKSAAN trigger
  └─ Age range: 0-60 bulan

TRANSAKSI_PEMERIKSAAN (Screening Header)
  ├─ N ─── 1 ─→ ANAK
  ├─ N ─── 1 ─→ GUDANG (posyandu yang screening)
  ├─ Trigger: after_insert → hitung Z-Score, set status_gizi + prioritas
  ├─ Z-Score BB/U: (actual_bb - median) / sd_1
  ├─ Z-Score TB/U: (actual_tb - median) / sd_1
  ├─ status_gizi: 'Berisiko Stunting' | 'Gizi Kurang' | 'Normal'
  └─ skala_prioritas: 1 | 2 | 3 (untuk alokasi paket gizi)

TRANSAKSI_PENGADAAN (Supply from Farmer Header)
  ├─ N ─── 1 ─→ PETANI_LOKAL
  ├─ N ─── 1 ─→ GUDANG (Gudang Pusat only)
  ├─ 1 ─── M ─→ PENGADAAN_DETAIL
  ├─ status_bayar: 'Pending' | 'Lunas'
  └─ Trigger: after_insert_detail → increment stok_log qty_in

PENGADAAN_DETAIL (Supply Items)
  ├─ N ─── 1 ─→ TRANSAKSI_PENGADAAN
  ├─ N ─── 1 ─→ KOMODITAS_PANGAN
  └─ Trigger: after_insert → stok_log.qty_in += jumlah_pasok

TRANSAKSI_DISTRIBUSI_INTERNAL (Internal Transfer Header)
  ├─ N ─── 1 ─→ GUDANG (id_gudang_asal = Gudang Pusat)
  ├─ N ─── 1 ─→ GUDANG (id_gudang_tujuan = Gudang Posyandu)
  ├─ 1 ─── M ─→ DISTRIBUSI_DETAIL
  ├─ status_kirim: 'Proses' | 'Diterima'
  └─ Constraint: id_gudang_asal ≠ id_gudang_tujuan

DISTRIBUSI_DETAIL (Transfer Items)
  ├─ N ─── 1 ─→ TRANSAKSI_DISTRIBUSI_INTERNAL
  ├─ N ─── 1 ─→ KOMODITAS_PANGAN
  ├─ Trigger before: validasi stok asal cukup
  └─ Trigger after: deduct asal qty_out, add tujuan qty_in

TRANSAKSI_PENYERAHAN_BANTUAN (Aid Distribution to Mother Header)
  ├─ N ─── 1 ─→ IBU
  ├─ N ─── 1 ─→ GUDANG (Posyandu warehouse)
  ├─ 1 ─── M ─→ PENYERAHAN_DETAIL
  ├─ skala_prioritas: 1 | 2 | 3 (auto-lookup dari anak.skala_prioritas)
  └─ Paket gizi auto-mapped berdasarkan prioritas

PENYERAHAN_DETAIL (Aid Items to Mother)
  ├─ N ─── 1 ─→ TRANSAKSI_PENYERAHAN_BANTUAN
  ├─ N ─── 1 ─→ KOMODITAS_PANGAN
  ├─ Trigger before: validasi stok posyandu cukup
  └─ Trigger after: deduct stok posyandu qty_out

STOK_LOG (Real-time Inventory)
  ├─ Composite PK: (id_gudang, id_komoditas)
  ├─ N ─── 1 ─→ GUDANG
  ├─ N ─── 1 ─→ KOMODITAS_PANGAN
  ├─ qty_current = qty_in - qty_out (GENERATED ALWAYS)
  ├─ Updated by triggers (pengadaan, distribusi, penyerahan)
  └─ Viewed by v_stok_gudang_realtime

ACTIVITY_LOG (Audit Trail)
  ├─ N ─── 1 ─→ USERS
  ├─ event: 'CREATE_ANAK', 'UPDATE_STOK', etc
  └─ For compliance & traceability
```

## 5. DATABASE VIEWS (4 UNTUK REPORTING)

### View 1: v_penyerapan_komoditas
```sql
Purpose: Track commodity absorption (in vs out)

SELECT
    k.id_komoditas,
    k.nama_komoditas,
    s.singkat AS satuan,
    COALESCE(SUM(pd.jumlah_pasok), 0) AS total_masuk,
    COALESCE(SUM(psd.jumlah_serah), 0) AS total_keluar,
    COALESCE(SUM(pd.jumlah_pasok), 0) - COALESCE(SUM(psd.jumlah_serah), 0) AS sisa_stok
FROM komoditas_pangan k
JOIN satuan s ON k.id_satuan = s.id_satuan
```

## 6. BUSINESS LOGIC & CONSTRAINTS

### Z-Score Calculation Logic

```
Formula: Z-Score = (Actual Value - Median) / (Median - SD-1)

Example:
  Anak: Budi, 6 bulan, L, BB = 5.2 kg
  Lookup standar (6 month, male, BB/U):
    median = 7.934 kg
    sd_minus_1 = 6.940 kg
  Z-Score = (5.2 - 7.934) / (7.934 - 6.940)
          = -2.734 / 0.994
          = -2.75 SD
  Status: 'Gizi Kurang' (between -2 and -3 SD)
  Prioritas: 2

Business Rule:
  IF Z-Score < -3 SD → 'Berisiko Stunting', Prioritas 1
  IF -3 <= Z-Score < -2 SD → 'Gizi Kurang', Prioritas 2
  IF Z-Score >= -2 SD → 'Normal', Prioritas 3
  IF ibu.is_pregnant = 1 → OVERRIDE to Prioritas 1 (regardless of Z-Score)
```

### Paket Gizi Allocation Logic

```
HARDCODED (tidak dari database, fixed di application):

Prioritas 1 (Berisiko Stunting / Ibu Hamil):
  ├─ Ikan Nila Segar: 1.5 kg
  └─ Telur Ayam: 10 butir
  Rationale: High protein + micronutrient dense

Prioritas 2 (Gizi Kurang):
  ├─ Ikan Nila Segar: 1.0 kg
  └─ Telur Ayam: 8 butir
  Rationale: Moderate protein support

Prioritas 3 (Normal / Monitoring):
  ├─ Sayur Hijau: 0.5 kg
  └─ Telur Ayam: 3 butir
  Rationale: Maintenance + micronutrient
```

### Stock Validation & Constraint Logic

```
BEFORE INSERT pengadaan_detail:
  └─ No validation (farm supplies usually available)

BEFORE INSERT distribusi_detail:
  └─ VALIDATE: stok_log.qty_current (gudang_asal) >= jumlah_kirim
     IF FAIL → SIGNAL SQLSTATE '45000' (prevent insert)

BEFORE INSERT penyerahan_detail:
  └─ VALIDATE: stok_log.qty_current (gudang_posyandu) >= jumlah_serah
     IF FAIL → SIGNAL SQLSTATE '45000' (prevent insert)

Purpose: Prevent over-allocation, ensure stock integrity
```

### Data Isolation Rules (RBAC + DB Level)

```
KADER:
  ├─ Can see: Ibu + Anak in own posyandu (WHERE id_gudang = SESSION[gudang_id])
  ├─ Can see: Own screening, distribution, penyerahan
  └─ Cannot see: Other posyandu data

PETANI:
  ├─ Can see: Own pengadaan transactions
  ├─ Can see: Own revenue (v_ekonomi_mitra)
  └─ Cannot see: Other farmer data

IBU:
  ├─ Can see: Own anak + pemeriksaan history
  ├─ Can see: Own penyerahan history
  └─ Cannot see: Other ibu/anak data

ADMIN:
  └─ Can see: All data (no filter)

Implementation:
  ├─ Application level: WHERE clause in queries
  ├─ SQL level: No explicit row-level security (v1)
  └─ Escalation: Code review + RBACHelper enforcement
```

## 7. KEY CONSTRAINTS

### Domain Constraints

```
users.role:
  ├─ ENUM('Admin', 'Kader', 'Petani', 'Ibu')
  └─ Only these 4 values allowed, immutable

gudang.jenis_gudang:
  ├─ ENUM('Pusat', 'Posyandu')
  ├─ 'Pusat': Exactly 1 per region (puskesmas)
  └─ 'Posyandu': 3-5 per region (posyandu)

anak.jenis_kelamin:
  ├─ ENUM('L', 'P')
  └─ Binary, required for WHO lookup

anak.st_gizi_skrg:
  ├─ Set by trigger after_insert_pemeriksaan
  ├─ Values: 'Berisiko Stunting', 'Gizi Kurang', 'Normal'
  └─ Immutable by user (auto-calculated)

stok_log.qty_current:
  ├─ GENERATED ALWAYS AS (qty_in - qty_out) STORED
  └─ Virtual column, always calculated, never directly set
```

### Referential Integrity Constraints

```
ibu.id_gudang → gudang.id_gudang [ON DELETE SET NULL]
  └─ If posyandu deleted, ibu's gudang becomes NULL (orphaned but not deleted)

anak.id_ibu → ibu.id_ibu [ON DELETE CASCADE]
  └─ If ibu deleted, all her children also deleted

petani_lokal.id_petani → users.id_user [ON DELETE RESTRICT]
  └─ Cannot delete user if petani record exists (protect data)

pengadaan_detail.id_pengadaan → transaksi_pengadaan [ON DELETE CASCADE]
  └─ If pengadaan header deleted, all detail rows also deleted

distribusi_detail.id_distribusi → transaksi_distribusi_internal [ON DELETE CASCADE]
penyerahan_detail.id_penyerahan → transaksi_penyerahan_bantuan [ON DELETE CASCADE]
```

### Uniqueness Constraints

```
users.username: UNIQUE NOT NULL
  └─ No duplicate usernames

ibu.NIK_ibu: UNIQUE NOT NULL
  └─ No duplicate NIK (national ID)

gudang: No explicit unique (allow duplicate names for different regions in future)

komoditas_pangan.nama_komoditas: UNIQUE NOT NULL
  └─ No duplicate commodity names

transaksi_pengadaan.no_kontrak: UNIQUE NOT NULL
  └─ Contract numbers are unique

transaksi_distribusi_internal.no_surat_jalan: UNIQUE NOT NULL
  └─ Transfer letter numbers are unique
```

### Check Constraints

```
transaksi_distribusi_internal:
  CHECK (id_gudang_asal <> id_gudang_tujuan)
  └─ Cannot transfer from warehouse to itself

stok_log.qty_in >= 0, qty_out >= 0
  └─ Stock cannot be negative (implicit via triggers)

anak.tgl_lahir <= CURRENT_DATE
  └─ Birth date cannot be in future
```
